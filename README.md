# Numerical Integration Error Analysis

## Objective

Implement composite numerical integration methods and investigate how their accuracy depends on the integrand and the number of subintervals. The project implements the **composite trapezoidal rule** and the **composite Simpson's 1/3 rule**, compares them on functions with known exact integrals, and uses the experiments to examine error and convergence behaviour.

Key questions studied:

- How does the absolute error shrink as the number of subintervals `n` grows?
- Do the observed convergence orders match theory (h² for trapezoidal, h⁴ for Simpson)?
- What happens for polynomials, rapid oscillation, sharp peaks, and endpoint singularities?
- When do floating-point rounding errors make order estimates meaningless?

## Methods

With `h = (b - a) / n` and nodes `x_i = a + i*h`:

- **Composite trapezoidal rule:** `T = h * [ (f(x0) + f(xn)) / 2 + sum_{i=1}^{n-1} f(xi) ]`. Error is O(h²). Exact for polynomials up to degree 1.
- **Composite Simpson's 1/3 rule:** `S = (h/3) * [ f(x0) + f(xn) + 4*sum(odd i) f(xi) + 2*sum(even i) f(xi) ]`. Requires `n` to be even. Error is O(h⁴). Exact for polynomials up to degree 3.
- **Absolute error:** `E = |approx - exact|`.
- **Observed order:** `p = log(E1/E2) / log(h1/h2)` for two consecutive step sizes. No order is reported when an error is at or below `1e-14`, because rounding noise dominates.

### Use the integration functions

```python
import math
from trapezoidal import composite_trapezoidal
from simpson import composite_simpson

# integral of sin(x) over [0, pi]; exact value is 2
print(composite_trapezoidal(math.sin, 0, math.pi, 4))   # 1.896118897937...
print(composite_simpson(math.sin, 0, math.pi, 4))       # 2.004559754984...
```

(Run from `src/` or add `src/` to `PYTHONPATH`.) Simpson's rule raises `ValueError` if `n` is odd or not positive.

### Run a convergence study

```python
import math
from error_analysis import convergence_study, format_table
from trapezoidal import composite_trapezoidal

rows = convergence_study(composite_trapezoidal, math.sin, 0, math.pi, 2.0,
                         [4, 8, 16, 32, 64])
print(format_table(rows))   # columns: n, h, approximation, abs error, order
```

Main functions in `error_analysis.py`: `absolute_error`, `observed_order`, `compute_errors`, `convergence_orders`, `convergence_study`, `format_table`.


The suite has 50 tests, all passing. Coverage by area:

1. **Trapezoidal rule:** used as the method under test in the convergence and error tests (order close to 2, exact for linear functions, order about 1.5 for sqrt(x)).
2. **Simpson's rule:** order close to 4 (using both a reference implementation and the real `simpson.py`), exact for cubics with no misleading order reported.
3. **Error and convergence analysis:** absolute error, observed order (known powers, symmetry, zero errors), input validation, NumPy compatibility, reversed intervals, duplicate or invalid `n` values, the rounding-error floor, and table formatting.
4. **Experiments and visualization:** verified by running `experiments.py` and checking the generated tables and plots against the report.

## Key Results

| Experiment | Observation |
|---|---|
| Smooth functions (e^x, sin x) | Observed orders approach 2 (trapezoidal) and 4 (Simpson). For e^x at n = 16, Simpson is about 3800 times more accurate. |
| Polynomial exactness | Trapezoidal is exact up to degree 1, Simpson up to degree 3. |
| sin(20x) | Coarse meshes cannot resolve the oscillation, so orders are erratic (trapezoidal order -0.81 at n = 4) until n is large enough. |
| 1/(1+25x²) | Simpson is worse than trapezoidal at n = 8 and 16. Its orders jump (7.2, 11.0) while the peak becomes resolved, and settle near 4 from n = 128. |
| sqrt(x) | Both methods drop to order about 1.5 because of the singular derivative at 0. The substitution x = t² turns it into a polynomial. |

Main conclusions: theoretical orders only appear once the mesh resolves the function, accuracy depends on smoothness, and order estimates from errors near 1e-14 are meaningless.

## Limitations

- Equally spaced nodes only; no adaptive refinement and no handling of unknown exact integrals.
- The integrand is evaluated one scalar at a time. The trapezoidal rule uses a Python loop, and Simpson's rule uses NumPy arrays.
- Singularities are not treated automatically.
